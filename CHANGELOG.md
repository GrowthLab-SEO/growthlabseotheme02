# Changelog

All notable changes to GrowthLab Theme 02. The version is in `style.css` and goes up with every update that is pushed:
patch (1.0.x) for fixes, minor (1.x.0) for new features or changes editors can see.

## 1.3.1 - 2026-10-29

### Fixed
- `npm run create-child` builds the new child theme right away. The theme loads only the compiled files of a child
  theme, so a new one looked unstyled until `npm run build:child` ran, a step the instructions left out.
- `README.md` and `CHILD-THEMES.md` list the steps to create a child theme in order: `npm install`, `create-child`,
  activate it, then `build:child` after every change.

### Check after updating
- Nothing on the sites: this release changes the build tools and the docs only.

## 1.3.0 - 2026-10-27

### Added
- `AI-RULES.md`: rules for building sites with AI on this theme (decision ladder for designs, content and
  editability rules, code standards, checklist). Read it with `CATALOG.md` and `CHILD-THEMES.md`.
- `CATALOG.md`: what the theme can build, generated by `npm run build` from the theme files: blocks with every field
  and option, heroes, page templates, post types, page and site options, shortcodes, the images and their contexts,
  the logo symbol and the default colors and fonts. `npm run verify` checks it is up to date.
- Every block has a description in its `block.json` (shown in the block inserter): what it is for and what content it
  needs.
- Child themes can change the sizes or loading of any theme image by its context, without overriding its template:
  `theme_set_picture_sizes('hero/*/side-portrait', max_size: 'large', min_size: 'content');` in the child's
  `functions.php`, or the `theme_picture_args` filter. The contexts are listed in `CATALOG.md` (Images).
- The default hero has the class `hero--default`, to style inner page heroes.

### Changed
- The child theme styles (`styles/main-min.css` and `style.css`) print after all the theme styles, including the block
  and card styles, as the child theme guide says. A child rule now wins over a block rule of the same specificity.
- Page - Sidebar (page editor): the field "Meu Text Content" of the sidebar boxes is now labeled "Menu Text Content" (same field).

### Fixed
- Field conditions that pointed to deleted fields were removed. ACF ignored them, so the edit screens don't change.

### Check after updating
- Child themes: rules of the child theme that lost to the block styles before now apply. Look at the pages of sites
  whose child theme styles blocks (e.g. spacing or colors that "never worked" may now show).
- ACF: "Sync available" for Block - FAQ, Block - Contact Form, Block - Office Locations and Page - Sidebar. Sync them.

## 1.2.0 - 2026-10-24

### Added
- Gravity Forms phone fields are masked with IMask.
- Child themes can have their own `styles/`, `js/` and `blocks/` folders, like the theme: the theme's gulp builds them
  (`npm run build:child -- --child=../<child folder>`, or the folders listed in `child-themes.json`) and the theme loads the built
  files and registers the child blocks. `npm run create-child` starts a child theme. See `CHILD-THEMES.md`.
- `CHILD-THEMES.md`: guide to build sites and child themes (overrides, helpers, filters, SCSS tokens and classes,
  custom properties, CSS practices).
- `npm run verify`: local check of the theme (PHP syntax, build, pages of the local site and a test child theme).
- Accessibility: visible keyboard focus outline, reduced motion support, desktop submenus open on keyboard focus, the
  closed mobile menu is out of the tab order, hidden Gravity Forms labels stay available to screen readers, decorative
  symbols printed with CSS are hidden from them and the video close button is bigger.
- Font sizes chosen in the WYSIWYG for parts of a title scale down on small screens, never below the title's own size
  at that screen (unless the chosen size is smaller) nor below 12px.
- Filters for child themes: `theme_page_hero_title`, `theme_main_script_data`, `theme_styled_select_data`,
  `<theme>_splide_blocks` and `<theme>_request_uses_splide`.

### Changed
- Image size `cover-tablet` is 1280x960 (it was 1280x600), like the other themes.
- The blog filters build the cards of their results from the theme's post card (and from its child theme override).
- Only the styles of the hero the page uses and of the cards it renders are printed, so the inline CSS is smaller.
- The theme functions are shared by the GrowthLab themes; the design data (default colors and fonts, excerpt lengths)
  is in `theme-functions/theme-config.php`.
- TinyMCE gets the theme colors as JSON, without the scripts that patched the color picker.
- "Clear block cache" is inside the "Theme Tools" menu of the admin bar.

### Fixed
- The blog filter buttons and the location cards of block widgets keep their styles.
- Items of ordered lists in formatted content are numbered.
- The first section after the hero and a floating CTA box render right away, without being clipped or jumping above
  the hero while the page loads. Sections further down keep rendering only when they get near the screen.

### Check after updating
- Purge the page cache of the site (the theme's own CSS cache updates by itself).
- Child themes with their own PHP (`functions.php`, template parts): the pages that use them render without errors.
- WYSIWYG fields in the editor: the color picker shows the theme colors and applies them.
- Titles with font sizes chosen in the WYSIWYG: they are now smaller on mobile and tablet.
- One page of each hero style and the blog, archive and search listings: styles look as before.
- Keyboard: Tab through the header menu; submenus open on focus.
- Regenerate the thumbnails (e.g. Regenerate Thumbnails plugin) so hero images on tablets use the new `cover-tablet`
  size. Until then they use the old one.
- Forms with a phone field: the mask works and the form submits.
- Blog filters: the filtered cards look like the cards of the listing.

## 1.1.0 - 2026-10-23

### Added
- Every Gravity Forms field (Contact Form block, footer form in Site Options and the page footer form in Page - Options)
  has a **Form Type** select: Gravity Form, Custom code or None. **Custom code** shows a **Form Code** textarea for the
  embed code or script of a third-party form (e.g. a CRM), printed as is. Forms saved before this keep their Gravity Form.

### Fixed
- Section content of blocks and the footer columns (Main Content, Text Content, FAQ answers, etc.) is no longer passed
  through `wp_kses_post()`, which removed iframes, scripts and forms pasted by editors. Titles and short card texts keep it.
- Paragraphs with right aligned images float to the right.
- Tapping a default card on mobile reveals its content.
- The team card symbol gets its styles (hidden on mobile, positioned from tablet up).
- The menu close button shows between 1024px and 1199px, where the off-canvas navigation is still used.
- Invalid grid lines in the header (the callout keeps the same size).
- Contrast of hovered options in the styled selects.

### Changed
- Site Options: "Posts Default Title Tag" and "Posts Default Image" are now labeled "Posts Cards Default Title Tag"
  and "Posts Cards Default Image". They only apply to the post cards of the blog, archive and search listings, not to
  the page title in the hero.

### Check after updating
- Pages with embeds in block content (forms, maps, videos): they print again. Remove any workaround that restored them.
- Contact forms: they keep their Gravity Form. To use a third-party form, set Form Type to Custom code.
- Team cards: the symbol is now hidden on mobile and positioned from tablet up.
- Field groups stored in the database: ACF shows "Sync available" for Site Options, Page - Options and
  Block - Contact Form.
